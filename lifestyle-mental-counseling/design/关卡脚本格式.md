# 反诈游戏 · 关卡脚本格式（CLS v1 · 对接 level-*.html）

> 目的：把可玩关卡的节点数据格式正式化，让策划能像填表一样产出「有选择分支 + 可退出点判定」的关卡，程序按统一引擎渲染即可。
> 配套：本格式与 `组件接口规范.md` 互补——CLS 管「关内剧情与分支」，组件接口规范管「结局后的复盘五组件」。
> 当前实现参考：`design/level-杀猪盘-可玩.html`（杀猪盘旗舰关卡，完整示范）。

---

## 0. 一个关卡 = 一份 CLS

```ts
interface CLS {
  meta:   { key:string; shape:string; hook:string; need:string; ex:string };
  phases: string[];                 // 熵曲线阶段，长度 = 5，与 review.series 对齐
  start:  string;                   // 起始场景 id
  scenes: Record<string, Scene>;    // 场景字典
  outcomes: { IMMUNE: Outcome; SCAMMED: Outcome };
  review:  ReviewData;              // 复盘（字段同组件接口规范 §1.1 的 CategoryData 子集）
}

interface Scene {
  phase:    string;                 // 须是 phases 中之一（用于阶段轨道高亮）
  exitPoint?: boolean;              // 是否「可退出点」——UI 提示 ⚠️
  text:     string;                 // 叙事文本（第二人称代入，用户语态）
  choices:  Choice[];
}

interface Choice {
  label:    string;                 // 选项文案
  next:     string;                 // 下一跳：场景 id | "IMMUNE" | "SCAMMED"
  safe?:    boolean;                // 仅 exitPoint 的安全选择置 true → 通向 IMMUNE
  exitNote?:string;                 // 安全选择命中时，结局里展示的「你避开了什么」
}

interface Outcome {
  cls:  "immune" | "scammed";       // 决定左线颜色与图标
  title:string;
  body: string;                     // 支持 <b> 等内联标签；IMMUNE 体内用 <b id="exit-at">
}
```

---

## 1. 字段约束（策划填表必读）

| 字段 | 必填 | 约束 | 说明 |
|---|---|---|---|
| `meta.key` | 是 | 同品类名 | 与组件接口规范的 `CategoryKey` 对齐 |
| `meta.shape` | 是 | `X ↓ → Y ↑` | 同组件接口规范 `shape` |
| `phases` | 是 | **长度 = 5** | 与 `review.series` 各数组长度一致 |
| `start` | 是 | 须是 `scenes` 的 key | 入口场景 |
| `scenes.*.phase` | 是 | ∈ `phases` | 决定阶段轨道高亮位置 |
| `scenes.*.exitPoint` | 否 | 默认 false | 标 true 的节点 UI 显示 ⚠️ 可退出点 |
| `scenes.*.text` | 是 | 第二人称、沉浸感 | 让玩家尝到「被填满的甜」 |
| `choices[].label` | 是 | — | — |
| `choices[].next` | 是 | 场景 id / `IMMUNE` / `SCAMMED` | 非法值引擎会卡死，须校验 |
| `choices[].safe` | 否 | 仅 exitPoint 用 | 置 true → 该选择通向 IMMUNE |
| `choices[].exitNote` | 否 | 配合 safe | 命中后写入结局 `<b id="exit-at">` |
| `outcomes.IMMUNE` | 是 | — | 免疫（安全）结局 |
| `outcomes.SCAMMED` | 是 | — | 被骗结局 |
| `review` | 是 | 同 CategoryData 子集 | 双屏/熵/CBT/三透镜/锦囊，详见组件接口规范 |

> ⚠️ **可退出点设计铁律**：每个关卡应至少在 2–3 个 `exitPoint` 节点提供 `safe:true` 选项；若某 `exitPoint` 节点**没有** safe 选项，则该点形同虚设，玩家无法在此止损（违背教学目的）。杀猪盘示范含 4 个有效可退出点。

## 2. 引擎判定逻辑（程序实现约定）

```
state: cur = CLS.start; exitAt = ""
render():
  高亮阶段轨道中 cur.phase 的位置
  渲染 cur.text 与 cur.choices
  exitPoint 节点：为每个 choice 加 ⚠️ 标；safe 选择加「安全·止损」标

choose(ch):
  if ch.exitNote: exitAt = ch.exitNote
  if ch.next in {IMMUNE, SCAMMED}: showOutcome(ch.next); return
  cur = ch.next; render()

showOutcome(type):
  隐藏舞台 → 显示结局 + 复盘(review)
  IMMUNE 且 exitAt 非空 → 写入 <b id="exit-at">
```

- `IMMUNE`：玩家在任一可退出点的 safe 选择触发 → 正向免疫结局。
- `SCAMMED`：玩家一路未起疑，或被引到崩盘节点无 safe 选项 → 被骗结局（仍进入复盘，照见扭曲）。
- **半赢处理**：如玩家已转账但后续起疑未扩大损失（杀猪盘 s6「找朋友核实」），归 `SCAMMED` 但 `exitNote` 文案强调「及时止损、损失最小」——既诚实又不羞辱。

## 3. 与熵曲线 / 组件接口规范的关系

- `CLS.phases` = `ReviewData.phases` = 熵曲线 X 轴阶段，三者必须同源。
- `ReviewData` 字段（left/right/note/shape/hint/phases/series/tr/dist/lenses/defense）**完全复用** `组件接口规范.md §1.1`，不另立字段。
- 关卡引擎只负责「剧情 + 分支 + 结局」，复盘渲染直接调用组件接口规范定义的五个组件（VictimCard / EntropyCurve / ThoughtRecord / LensPanel / Defense）。

---

## 4. 新增 / 改造关卡清单（策划 + 程序）

1. 复制 `level-杀猪盘-可玩.html` 的 `CLS` 块，改 `meta / phases / scenes / review`。
2. 设计剧情树：从 `start` 出发，养熟→引投→加码→崩盘 各阶段布点。
3. 至少 2–3 个 `exitPoint` 节点，每个都放 `safe:true` 选项（可退出点判定生效）。
4. 确保每条路径最终落在 `IMMUNE` 或 `SCAMMED`（无死循环、无悬空 `next`）。
5. `review` 套用对应品类数据（见 `design/受害者心理模型-*.md` 与 `design/受骗复盘debrief-*.md`）。
6. `phases` 长度 = 5，`review.series` 各数组长度 = 5，末端≈95。
7. 自检：跑一遍「全 safe」路径应到 IMMUNE；跑一遍「全风险」路径应到 SCAMMED。

## 5. 与合集框架的衔接

多关卡合集（`anti-fraud-collection.html`）用一个**通用引擎**加载多份 CLS：
- 合集持有 `LEVELS: CLS[]`，按 `levelOrder` 控制解锁（建议：刷单→杀猪盘→养老→公检法，情绪负荷递增）。
- 关卡地图点选 → 通用引擎以该 CLS 为数据源运行 → 完成（IMMUNE 或 SCAMMED 都算「已体验并复盘」）→ 解锁下一关、进度 +1。
- 因此新增一类关卡 = 新增一份 CLS 文件/数据 + 在 `LEVELS` 注册，**引擎零改动**。
