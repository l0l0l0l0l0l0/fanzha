# 反诈游戏 · 组件接口规范（v1 · 对接原型 anti-fraud-prototype.html）

> 目的：把可运行原型里的数据模型与组件边界正式化，让程序 / 策划能照此生产、扩展、联调四类诈骗关卡。
> 适用范围：双屏对比、熵曲线、CBT 思维记录、三透镜复盘、防御锦囊 五个组件，以及其上层数据容器 `DATA`。
> 当前实现参考：`design/anti-fraud-prototype.html`（单文件零依赖，可直接打开）。

---

## 0. 组件架构

```
DATA (品类字典)
 ├─ VictimCard      ①双屏对比 + 元数据（hook / need / ex / left / right / note）
 ├─ EntropyCurve    ②熵曲线（shape / hint / phases / series）
 ├─ ThoughtRecord   ③CBT 思维记录（tr 五栏 + dist 标注）
 ├─ LensPanel       ④三透镜复盘（lenses）
 └─ Defense         ⑤防御锦囊（defense）
```

- `DATA` 是**唯一数据源**：一个以「品类名」为 key 的字典。渲染时只切换 `cur`（当前品类），不切换结构。
- 任意品类共用同一套字段键名，只换取值——这是「多品类合集 = 只换数据不换代码」的前提。

## 1. 数据模型 DATA

### 1.1 类型定义

```ts
type CategoryKey = "杀猪盘" | "刷单返利" | "冒充公检法" | "养老诈骗" | string;

interface DistItem { t: string; l: string }      // 认知扭曲标注：t=玩家原话, l=命中的扭曲类型
interface LensItem { t: string; b: string }        // 透镜卡：t=透镜名, b=解读正文

interface EntropySeries {
  cog:  number[];   // 认知熵（对方是谁的不确定性）0–100，长度 = phases.length
  beh:  number[];   // 行为熵（行为反常度）0–100
  mean: number[];   // 意义熵（关系算什么）0–100
}

interface CategoryData {
  hook:  string;            // 核心钩子（一句话）
  need:  string;            // 需求空白（受害者被利用的心理缺口）
  ex:    string;            // 示例角色（如「林姐（38 岁，离异独居）」）
  left:  string;            // 双屏·你以为的（代入视角，用户语态）
  right: string;            // 双屏·实际上的（真相，含交叉熵 H(p,q) 解读）
  note:  string;            // 不羞辱金句（收口，正向）
  shape: string;            // 熵曲线形状描述（如「养熟 ↓ → 背叛 ↑」）
  hint:  string;            // 熵曲线解读（养熟/崩盘期语义）
  phases: string[];         // 阶段名，长度 = 5，与 series 各数组对齐
  series: EntropySeries;    // 三条熵线数值（0–100）
  tr: {
    event:   string;        // 事件
    thought: string;        // 想法
    emotion: string;        // 情绪（建议「情绪 百分比%，如 恐惧 90%」）
    behavior:string;        // 行为
    healthy: string;        // 更健康的想法（对照）
  };
  dist:  DistItem[];        // 命中的认知扭曲（点「标注」后渲染）
  lenses: LensItem[];       // 三透镜（长度 = 3）
  defense: string[];        // 防御锦囊（长度 = 3）
}

const DATA: Record<CategoryKey, CategoryData> = { /* 见原型 */ };
```

### 1.2 字段约束（策划填表必读）

| 字段 | 必填 | 约束 | 说明 |
|---|---|---|---|
| `hook` | 是 | ≤ 18 字 | 核心心理钩子，决定该类的「甜」是什么 |
| `need` | 是 | — | 需求空白，照 victim card 第 2 字段 |
| `ex` | 是 | 含年龄/处境 | 示例角色，便于玩家代入 |
| `left` | 是 | 用户语态、第一人称 | 让玩家尝到「被填满的甜」 |
| `right` | 是 | 含「交叉熵 H(p,q)」字样 | 真相 + 熵解读，必须点名 q 崩塌 |
| `note` | 是 | 不羞辱、正向 | 收口金句，忌说教/指责 |
| `shape` | 是 | `X ↓ → Y ↑` 格式 | 曲线形状一句话 |
| `hint` | 是 | — | 养熟/崩盘（或对应期）语义 |
| `phases` | 是 | **长度固定 = 5** | 阶段名，须与 series 对齐 |
| `series.*` | 是 | **长度 = 5，值 0–100** | 末端（第 5 点）建议 = 95（崩盘/揭示） |
| `tr.*` | 是 | 五栏齐全 | 预填示例，玩家可改 |
| `dist` | 是 | 2–4 条 | 每条 t 须出现在 `tr.thought` 里 |
| `lenses` | 是 | **长度 = 3** | 透镜名建议含「CBT / 行为经济学或社会心理学或依恋 / 叙事或危机应激」 |
| `defense` | 是 | **长度 = 3** | 每条含一个「100% 是 X」铁律更佳 |

> ⚠️ 长度约定：四类已定稿数据均满足 `phases=5 / series=5 / lenses=3 / defense=3`。新增品类**必须保持同一长度**，否则熵曲线与卡片布局会错位。

## 2. 组件接口详述

### 2.1 VictimCard（双屏对比 + 元数据）
- 输入：`hook, need, ex, left, right, note`
- 渲染位：`.card h2#h-hook` 区；`meta` 三 span（`#m-hook / #m-need / #m-ex`）；`.duo` 双 box（`#d-left / #d-right`）；`.note#d-note`
- 设计约束：`left` 用冷色块（信任错觉），`right` 用暖红块（真相）；`note` 金色左线收口。

### 2.2 EntropyCurve（熵曲线）
- 输入：`shape, hint, phases, series`
- 渲染位：`#h-ent`（标题含 `shape`）、`#chart`（SVG viewBox 0 0 600 300）、`#ent-hint`
- 数据格式：`series` 三条线，键名固定 `cog / beh / mean`，对应颜色见 §4。
- 动画：用 `pathLength="1"` + `stroke-dashoffset` 描边动画，`1.1s` 缓动，三条线错位 `0.15s`。
- 坐标系：`v/100` 映射 y；`i/(n-1)` 映射 x；n = `phases.length`。

### 2.3 ThoughtRecord（CBT 思维记录）
- 输入：`tr`（五栏）、`dist`（标注）
- 渲染位：五个 `.row input`（`#tr-event / #tr-thought / #tr-emotion / #tr-behavior / #tr-healthy`）；按钮 `analyze()`；结果区 `#tr-dist`
- 交互：`analyze()` 读 `DATA[cur].dist`，渲染为 `.tag`（「原话」→ 扭曲类型）。
- 约束：`dist[].t` 须能在 `tr.thought` 中找到，否则玩家会觉得「我没说过这话」。

### 2.4 LensPanel（三透镜复盘）
- 输入：`lenses`（长度 3）
- 渲染位：`#lenses`（三栏 `.lens`，`<b>透镜名</b><br>正文`）
- 设计约束：三透镜应覆盖「认知 / 经济或社会 / 叙事或应激」三个层面，避免同质。

### 2.5 Defense（防御锦囊）
- 输入：`defense`（长度 3）
- 渲染位：`#defense`（`<ul><li>`），每条可加 `<b>•</b>` 前缀。

## 3. 渲染与状态约定

| 项 | 约定 |
|---|---|
| 当前品类 | 变量 `cur`（默认 `"杀猪盘"`） |
| 切换 | `tab.onclick → cur = k; render()` |
| 重渲染 | `render()` 统一刷新五个组件 + `renderChart()` |
| 熵曲线重绘 | 每次 `render()` 调 `renderChart(d)`，先 `svg.innerHTML=s` 再触发动画 |
| 认知扭曲 | 仅在玩家点「标注命中的认知扭曲」后展开（`analyze()`） |

> 接入真实后端时：`DATA` 可整体替换为接口返回（字段键名不变即可）；`render()/renderChart()/analyze()` 无需改动。

## 4. 配色令牌（与 CSS `:root` 对齐）

| 令牌 | 值 | 用途 |
|---|---|---|
| `--bg` | `#0f1320` | 页面底 |
| `--panel` | `#171c2e` | 卡片底 |
| `--acc` | `#5b8cff` | 强调/认知熵线 |
| `--warn` | `#ff7a7a` | 警示/意义熵线/扭曲标 |
| `--gold` | `#ffcf6b` | 收口金句/行为熵线 |
| `--ok` | `#4fd6a3` | 透镜标题/正向 |

熵曲线三色：`cog=#5b8cff / beh=#ffcf6b / mean=#ff7a7a`，**四类一致**，不可按品类改色（否则跨类对比失真）。

## 5. 新增品类接入清单（程序 / 策划）

1. 在 `DATA` 增加一条 `key: CategoryData`，key 即 tab 名。
2. 填齐 §1.2 全部字段，严守长度：`phases=5 / series 各 5 / lenses=3 / defense=3`。
3. `right` 必含「交叉熵 H(p,q)」字样；`shape` 用 `X ↓ → Y ↑`。
4. `dist[].t` 逐条核对确实出现在 `tr.thought`。
5. 确认 `tab` 自动生成（原型 `buildTabs()` 遍历 `DATA` key，无需改代码）。
6. （可选）补该类专属正向收口分支（如公检法「挂断→核实」胜利结局）。
7. 校验：打开原型切到新类，熵曲线末端≈95、双屏/三透镜/锦囊均渲染、点标注出 tag。

---

## 6. 伦理红线（四类通用，合集必守）

1. **不真骗**：模拟的是已被拆解的套路；绝不在游戏内向玩家索取真实转账、验证码、房产证。
2. **不收隐私**：UI 不采集玩家真实姓名、手机号、证件、家庭关系。
3. **知情同意 + 警示**：进入关卡前强提示「本关为反诈模拟，遇疑拨 96110」；公检法类情绪负荷最重，须提供「一键跳过 / 易退出」。
4. **不羞辱只照见**：所有 `note / 复盘文案` 正向收口，绝不指责「你活该」。
5. **给真实出口**：每关底部固定 96110 / 110 / 国家反诈中心 App。
6. **不生成伪公文**：冒充公检法类不得产出可误认的真实公文模板、假通缉令下载物。

## 7. 后续可扩展点（不在 v1 范围）

- `VictimCard` 增加「可退出转折点」标记（原型已用 `phases` 含 3–4 个教学点，可加 `exitPoints:number[]` 高亮）。
- `EntropyCurve` 支持玩家**实时熵值**回写（根据其在关内选择推高/压低曲线）。
- `ThoughtRecord` 从「预填示例」升级为「玩家自由输入 + LLM 实时标注扭曲」（需后端）。
- 四类合集加 `levelOrder` 字段控制解锁顺序（建议：刷单→杀猪盘→养老→公检法，情绪负荷递增）。
