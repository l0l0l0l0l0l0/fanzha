# 抖音小游戏迁移完整实施方案

## 概述

将现有 React + Vite + Tailwind 反诈游戏平台迁移为抖音原生小游戏。**用户已确认三项关键决策**：

1. **开发框架**：原生抖音小游戏开发（`tt.*` API + Canvas 2D，不使用 Taro/Cocos）
2. **项目结构**：替换现有 `/src` 代码，移除 React/Vite/Tailwind，最终只交付小游戏
3. **改造范围**：一次全部改造完成 Hub + 4 个游戏 + Briefing + ResultCard

**核心技术策略**：保留引擎层（GameEngine/Particle/Renderer/4 个游戏引擎）的 95% 代码不动，新建 Canvas UI 框架（Scene + SceneDirector + widgets）替代所有 React 组件，新建平台适配层（`src/platform/tt.ts`）封装 `tt.*` API。

### 3.5 `src/ui/Scene.ts`（场景基类）

```ts
import type { SceneDirector } from "./SceneDirector";

export abstract class Scene {
  protected director: SceneDirector;
  constructor(director: SceneDirector) { this.director = director; }
  enter(params?: Record<string, unknown>): void {}
  exit(): void {}
  abstract update(dt: number): void;
  abstract render(ctx: CanvasRenderingContext2D, screenW: number, screenH: number): void;
  handleTouch(type: "start" | "move" | "end", x: number, y: number, touchId: number): boolean { return false; }
  pause(): void {}
  resume(): void {}
}
```
说明：`handleTouch` 返回 `true` 表示该触摸已被消费（用于 consumedTouchIds 机制）。

### 3.6 `src/ui/SceneDirector.ts`（场景管理 + 主循环 + 触摸路由）

核心职责：
1. 首次调用 `tt.createCanvas()` 获取显示画布，设置 `canvas.width = screenWidth * pixelRatio`，`ctx.scale(dpr, dpr)`，后续渲染在逻辑像素坐标系
2. 维护 `sceneStack: Scene[]`，提供 `push/replace/pop` 导航 API
3. 主循环 `requestAnimationFrame` 驱动：`current.update(dt)` → `current.render(ctx, screenW, screenH)`
4. 全局注册一组 `tt.onTouch*` 回调，转发给 `currentScene.handleTouch`
5. 监听 `tt.onHide/onShow` 实现 `pause/resume`
6. 提供 `createOffscreenCanvas()` 给游戏场景创建引擎画布
7. 提供 `blitContain(src, ctx, screenW, screenH)` 将引擎画布按 contain 模式 blit 到显示画布（含 letterbox 黑边填充 `#0A1929`）
8. 提供 `screenToLocal(x, y, canvasW, canvasH)` letterbox 逆变换
9. 维护 `consumedTouchIds: Set<number>` 解决 Scene 按钮 vs 引擎 InputManager 拖拽的触摸冲突

关键 API：
```ts
class SceneDirector {
  push(scene: Scene, params?: Record<string, unknown>): void;
  replace(scene: Scene, params?: Record<string, unknown>): void;
  pop(): void;
  start(): void;
  stop(): void;
  createOffscreenCanvas(): GameCanvas;
  blitContain(src: GameCanvas, ctx: CanvasRenderingContext2D, screenW: number, screenH: number): void;
  screenToLocal(x: number, y: number, canvasW: number, canvasH: number): { x: number; y: number };
  get safeArea(): { top: number; bottom: number; left: number; right: number };
  get menuButton(): { top: number; right: number; width: number; height: number };
  consumedTouchIds: Set<number>;
}
```

**触摸路由流程**：
```
tt.onTouchStart(res)
  → SceneDirector.dispatchTouch("start", res)
    → 取 changedTouches[0]
    → 检查 consumedTouchIds（move/end 时若已消费则跳过）
    → currentScene.handleTouch("start", x, y, touchId)
      → 返回 true 表示消费，加入 consumedTouchIds
      → 返回 false 表示未消费，由引擎 InputManager 处理
```

## 六、关键技术决策

### 6.1 画布尺寸适配（Letterbox 策略）

引擎用固定分辨率（480×800 / 960×540 / 540×960），显示画布为全屏。采用 **离屏画布 + contain blit** 方案：

- 每个游戏 Scene 创建一个离屏画布（`tt.createCanvas()` 非首次调用）
- 引擎渲染到离屏画布（固定分辨率）
- SceneDirector.blitContain 将离屏画布按 `scale = min(screenW/canvasW, screenH/canvasH)` 缩放并居中 blit 到显示画布
- 黑边填充 `#0A1929`
- 触摸坐标通过 `screenToLocal` 逆变换映射到引擎画布坐标

**不修改引擎坐标系统**，保持引擎代码不变。

### 6.2 横竖屏切换

- `game.json` 默认 `deviceOrientation: "portrait"`
- Manager 和 BombIsland 进入战斗时调用 `tt.setOrientation("landscape")`，退出时恢复 `"portrait"`
- 若 `tt.setOrientation` 不可用，退化为竖屏 letterbox（引擎画布缩放适配竖屏宽度）

### 6.3 触摸冲突解决（consumedTouchIds 机制）

Thunder 和 BombIsland 的引擎 InputManager 注册了全局 `tt.onTouch*`，与 SceneDirector 的全局触摸监听并存。解决：

1. SceneDirector 维护 `consumedTouchIds: Set<number>`
2. `handleTouch` 返回 `true` 表示消费，加入 `consumedTouchIds`
3. InputManager 在 `onTouchStart` 回调中检查 `director.consumedTouchIds.has(identifier)`，已消费则忽略
4. `handleTouch("end")` 时从 `consumedTouchIds` 删除

这样按钮区域和拖拽区域不冲突。

### 6.4 字体加载

- 通过 `tt.loadFont` 加载 ZCOOL KuaiLe / Noto Sans SC / JetBrains Mono
- 失败时静默 catch，退化为系统字体（PingFang SC / 系统等宽）
- Renderer.ts 中字体字符串已含 fallback，无需修改

### 6.5 构建工具

**决策**：使用 esbuild（非 tsc 编译，非 Vite）。

- esbuild 自动解析 `@/` 别名（通过插件）、tree-shaking、速度快
- 输出单个 `game.js` 文件（小游戏入口），无分包需求
- `format: "cjs"` 确保小游戏环境兼容
- `sourcemap: "linked"` 生成 `.map` 文件便于调试
- 保留 `@/` 别名，无需修改现有 import 路径

### 6.6 滚动支持

HubScene 内容可能超出屏幕。实现简单 Canvas 滚动：
- Scene 维护 `scrollY` 偏移量和 `contentH`
- 触摸拖拽更新 `scrollY`（限制在 `[0, contentH - screenH]`）
- `render` 时 `ctx.save(); ctx.translate(0, -scrollY); /* 内容 */; ctx.restore()`
- 顶部导航栏固定不滚动

## 十、假设与决策

### 10.1 关键假设
1. 抖音小游戏环境支持全局 `AudioContext` 构造器（通过 `globalThis.AudioContext` 或 `GameGlobal.AudioContext`）
2. `tt.createCanvas()` 首次返回显示画布，后续返回离屏画布
3. `requestAnimationFrame` / `cancelAnimationFrame` / `performance.now()` 全局可用
4. `tt.setOrientation` 可用于运行时横竖屏切换（若不可用则退化为竖屏 letterbox）
5. 字体文件可打包到 `assets/fonts/` 并通过 `tt.loadFont` 加载
6. 主包代码量在 4MB 以内（无分包需求）

### 10.2 已确认决策
1. **开发框架**：原生 tt.* API（不使用 Taro/Cocos）
2. **项目结构**：替换现有 /src 代码
3. **改造范围**：一次全部改造
4. **画布适配**：离屏画布 + contain blit（不修改引擎坐标系统）
5. **构建工具**：esbuild（保留 `@/` 别名，无需修改 import 路径）
6. **触摸冲突**：consumedTouchIds 机制
7. **字体**：`tt.loadFont` + 系统字体 fallback
8. **横屏**：`tt.setOrientation` 运行时切换

### 10.3 风险与缓解
| 风险 | 缓解措施 |
|---|---|
| `tt.setOrientation` 不可用 | 退化为竖屏 letterbox（引擎画布缩放适配竖屏宽度） |
| WebAudio API 部分支持不全 | `createAudioContext` 返回 null 时静默无音，游戏继续运行 |
| 字体加载失败 | 静默 catch，退化为系统字体（PingFang SC） |
| 包大小超 4MB | 启用 esbuild minify，必要时拆分子包 |
| 触摸精度不足 | 按钮最小 44×44 逻辑像素，符合移动端触控规范 |
